# Decisions & Open Questions

Add an entry whenever a design decision is made or changed. Agents: **don't decide anything listed under Open Questions yourself.** Implement the stated default only if the entry gives one, and point it out in your summary.

## Decisions

| ID | Decision | Rationale | Status |
| --- | --- | --- | --- |
| D-001 | **React Native + Expo (SDK 57)** frontend, TypeScript strict, Expo Router | Client requires both iOS and Android from one codebase | Accepted (Design v1) |
| D-002 | ~~**Strapi 5** as backend + CMS~~ → **Sanity** for content, **Supabase** for resident data and logic (D-024) | Non-technical Foundation staff need an easy admin UI | **Superseded 2026-10-19** by D-024 |
| D-003 | **Supabase** for Postgres, Auth and Storage (chosen over Firebase) | Relational data fits Postgres. Official RN support. Free tier | Accepted (Design v1) |
| D-004 | ~~The app talks to Strapi for all data~~. The app reads public content from **Sanity** and resident data from **Supabase directly**, with **Row Level Security as the authorization layer** | Strapi removed (D-024). Design v1's original wording ("RLS enforces rules at the database level") now applies as written | **Revised 2026-10-19** |
| D-005 | Role and status live in Supabase `profiles` (not JWT user metadata). Only admin-only database functions can change them | Role can't be forged through user-editable metadata | Revised 2026-10-19 (was a Strapi `profile`) |
| D-006 | Resident uploads go **straight to Supabase Storage** under RLS: `blight-photos` (public read), `inquiry-attachments` (private, owner + admins). Staff images (listings, thumbnails) live in Sanity | Design v1: files in Supabase Storage, DB stores references | Revised 2026-10-19 |
| D-007 | Push through **Expo Push Service** (`expo-notifications`), sent by Supabase Edge Functions. Publishing an alert in Sanity triggers a webhook to the `send-alert` function | Easiest cross-platform path, no server to host | Revised 2026-10-19 |
| D-008 | **Continuous Native Generation**: `ios/` and `android/` are gitignored and generated by `expo prebuild` (or automatically by `expo run:*`) | Committed native folders drift from `app.json` config plugins (`expo-sqlite`, `expo-location`, …) | Accepted. Never hand-edit `ios/`/`android/`; change `app.json`/`app.config.ts` and rebuild |
| D-009 | Tooling: ESLint (`eslint-config-expo` flat) + Prettier, `tsc --noEmit`, Jest (`jest-expo`) + React Native Testing Library, GitHub Actions CI | Expo-recommended defaults | Accepted (this repo) |
| D-010 | Node **22 LTS** (`.nvmrc`) | LTS for every toolchain (Expo SDK 57, Sanity Studio needs ≥ 22.12, Supabase CLI) | Accepted |
| D-011 | Blight status lifecycle `submitted → under_review → reported_to_city → resolved`, plus `removed` (moderation). Soft delete only | Combines the two status lists in the Iteration Plan. Admin log "call backs" need retained records | Proposed |
| D-012 | Email + password is the sign-in method. Phone is collected but not verified in v1 | SMS costs money and needs a provider decision (Q-002) | Accepted. The Figma "Phone or email" field is shown as "Email" until Q-002 |
| D-013 | The **Figma "Design Reference" file** is the visual source of truth: https://www.figma.com/design/HCQobhdAtHlnFF2XCV3pBX/Design-Reference. Tokens are mirrored in `src/constants/theme.ts`; brand/art/map assets are exported to `assets/` | Client-approved prototype and brand guide | Accepted |
| D-014 | Navigation follows the prototype: a **custom floating tab bar** (Home, Events, Housing, Library) plus a separate round **Report** button that opens the report flow as a full-screen modal | `NativeTabs` can't render the separate Report button or the prototype's look on Android | Accepted |
| D-015 | **Light mode only** for v1 (`userInterfaceStyle: light`) | The Figma file only defines a Light color mode | Accepted; revisit if a dark palette is designed |
| D-016 | **Demo mode**: when the Sanity vars are unset the app serves bundled sample content (`src/lib/api/mock-data.ts`); when the Supabase vars are unset, sign-in and resident data are simulated on the device (staff sign-in shows admin tools) | Lets anyone build, test and demo the app with no keys or backend | Accepted. Never ship a store build without the env vars |
| D-017 | **Local builds without EAS**: `npm run ios:device` / `ios:sim` build a Release app with Xcode on the developer's machine, signed with `APPLE_TEAM_ID` from `.env` | Faster iteration than EAS cloud builds, no Expo Go limitations | Accepted. EAS stays available for store builds |
| D-018 | Data fetching through **TanStack Query** hooks (`src/lib/api/queries.ts`) over a typed `fetch` client | Caching, refetch on pull-to-refresh, loading/error states for free | Accepted |
| D-019 | Report categories expanded to the prototype's six (`abandoned_building`, `standing_water`, `air_odor` added); reports have `keepNamePrivate`; housing adds `home_repair` and `housing-listing` | Figma prototype screens | Accepted (see data-model.md) |
| D-020 | Route auth pattern: resident and admin routes use `auth: false` plus the `global::is-authenticated` / `global::is-admin` policies. Public reads keep Strapi's scope check, granted to the Public role at bootstrap, and a `supabase` content-API strategy maps signed-in users onto Public permissions | Supabase tokens would otherwise 401 on public core routes (plan 001, Q-A) | Superseded 2026-10-19 (Strapi removed; see D-024) |
| D-021 | Backend tests run on a throwaway SQLite file per test file. JWTs are verified with `jose@^5` (CommonJS). `sharp` strips photo EXIF, so **HEIC blight photos are rejected** and the app sends JPEG | Fast CI without Docker; privacy of photo GPS data | Superseded 2026-10-19 (Strapi removed; see D-024) |
| D-022 | Business rules (last-admin invariant, append-only activity log, blight `statusHistory`, reminder cleanup) live in Strapi **Document Service middleware**, so edits from the admin panel obey them too | One enforcement point for app and admin panel | Superseded 2026-10-19 (Strapi removed; see D-024) |
| D-023 | External calls are opt-in: `PUSH_ENABLED`, `ENVIRONMENT_SYNC_ENABLED`, `AIRNOW_API_KEY`. District bounds come from `DISTRICT_BBOX` | Dev and test never hit external services | Superseded 2026-10-19 (Strapi removed; see D-024) |
| D-024 | **Replace Strapi with Sanity + Supabase.** Sanity (project `nxvenp1m`, dataset `production`) holds staff-edited content and app text, edited in a standalone **Sanity Studio** (`studio/`). Supabase holds auth, resident data (profiles, reports, inquiries, reminders, push tokens, admin log, environment readings) and logic (RLS, database functions, Edge Functions). No Next.js app | Strapi needs a paid always-on host. Sanity's free plan and hosted Studio give staff a polished editor. Supabase covers the rest on its free tier | Accepted 2026-10-19 (team) |
| D-025 | Sanity dataset is **public** (read without a token); the app queries the CDN API directly. Nothing private is ever stored in Sanity | Content is public by nature; no secret in the app | Accepted |
| D-026 | **Contract and RLS tests run against the hosted dev projects** (Supabase `lxwkbstypsyiscjegvgp`, Sanity `production`), so the whole team can verify the same data. Tests clean up after themselves | Team preference: one shared source of truth over local mock databases | Accepted |
| D-027 | Editable app text lives in the Sanity **App text** singleton (`appCopy`). The app caches it on the device and falls back to built-in wording for blank fields | Copy changes without app releases; works offline | Accepted |
| D-028 | iOS builds compile Expo modules **from source** (`expo-build-properties` → `ios.usePrecompiledModules: false`) and adopt the **UIKit scene lifecycle** (`ios.enableSceneSupport: true`, needs Expo ≥ 57.0.23; remove on SDK 58) | Xcode 27.1 (Swift 6.4) can't load Expo SDK 57's precompiled frameworks (built with Swift 6.3.1), and the iOS 27 SDK requires the scene lifecycle. Building from source is slower once but survives future Xcode updates | Accepted 2026-10-26 |
| D-029 | The Home and neighborhood screens use the **phone's location to find the neighborhood, on the device**, against the City of Atlanta's official Neighborhoods layer (bundled in `src/data/neighborhoods.json`, refreshed with `scripts/fetch-neighborhoods.py`). Order: detected neighborhood → profile's saved neighborhood → "Council District 3". Location is asked for only when the resident taps "Use my location", and coordinates never leave the phone. A signed-in resident without a saved neighborhood gets the detected one saved to their profile | Accurate per-neighborhood art and info without sending location to a server | Accepted 2026-10-26 |
| D-030 | Notification permission is asked during onboarding, or **once** on first reaching Home for people who skipped onboarding. Profile shows a "notifications are off" card with a button that asks or opens Settings | Sign-in from the welcome screen used to skip the only prompt | Accepted 2026-10-26 |
