# Decisions & Open Questions

Add an entry whenever a design decision is made or changed. Agents: **don't decide anything listed under Open Questions yourself.** Implement the stated default only if the entry gives one, and point it out in your summary.

## Decisions

| ID | Decision | Rationale | Status |
| --- | --- | --- | --- |
| D-001 | **React Native + Expo (SDK 57)** frontend, TypeScript strict, Expo Router | Client requires both iOS and Android from one codebase | Accepted (Design v1) |
| D-002 | **Strapi 5** as backend + CMS (chosen over Payload) | Non-technical Foundation staff need an easy admin UI for events, resources and moderation | Accepted (Design v1) |
| D-003 | **Supabase** for Postgres, Auth and Storage (chosen over Firebase) | Relational data fits Postgres. Official RN support. Free tier | Accepted (Design v1) |
| D-004 | Strapi uses Supabase Postgres in schema **`strapi`**. The app talks to Strapi for **all** data, and to Supabase **only for auth** | Design v1 says "no broad client-side DB access". One authorization layer is simpler to reason about than RLS + Strapi policies together | Accepted (plan 001 approved). Refines Design v1's RLS wording: RLS stays as deny-by-default protection, while Strapi policies enforce the actual rules |
| D-005 | Strapi verifies **Supabase JWTs** (JWKS). App role and status live on the Strapi `profile` content type. Strapi users-permissions login is not used | Single identity provider. Role can't be forged through user-editable metadata | Accepted (plan 001 approved) |
| D-006 | Uploads go to **Supabase Storage through the S3 provider** in Strapi. Housing attachments go in a private bucket with signed URLs | Design v1: files in Supabase Storage, DB stores references | Proposed |
| D-007 | Push through **Expo Push Service** (`expo-notifications`), sent from Strapi | Easiest cross-platform path with EAS | Proposed |
| D-008 | **Continuous Native Generation**: `ios/` and `android/` are gitignored and generated by `expo prebuild` (or automatically by `expo run:*`) | Committed native folders drift from `app.json` config plugins (`expo-sqlite`, `expo-location`, …) | Accepted. Never hand-edit `ios/`/`android/`; change `app.json`/`app.config.ts` and rebuild |
| D-009 | Tooling: ESLint (`eslint-config-expo` flat) + Prettier, `tsc --noEmit`, Jest (`jest-expo`) + React Native Testing Library, GitHub Actions CI | Expo-recommended defaults | Accepted (this repo) |
| D-010 | Node **22 LTS** (`.nvmrc`) | Strapi 5 supports LTS only. Expo SDK 57 supports it | Accepted |
| D-011 | Blight status lifecycle `submitted → under_review → reported_to_city → resolved`, plus `removed` (moderation). Soft delete only | Combines the two status lists in the Iteration Plan. Admin log "call backs" need retained records | Proposed |
| D-012 | Email + password is the sign-in method. Phone is collected but not verified in v1 | SMS costs money and needs a provider decision (Q-002) | Accepted. The Figma "Phone or email" field is shown as "Email" until Q-002 |
| D-013 | The **Figma "Design Reference" file** is the visual source of truth: https://www.figma.com/design/HCQobhdAtHlnFF2XCV3pBX/Design-Reference. Tokens are mirrored in `src/constants/theme.ts`; brand/art/map assets are exported to `assets/` | Client-approved prototype and brand guide | Accepted |
| D-014 | Navigation follows the prototype: a **custom floating tab bar** (Home, Events, Housing, Library) plus a separate round **Report** button that opens the report flow as a full-screen modal | `NativeTabs` can't render the separate Report button or the prototype's look on Android | Accepted |
| D-015 | **Light mode only** for v1 (`userInterfaceStyle: light`) | The Figma file only defines a Light color mode | Accepted; revisit if a dark palette is designed |
| D-016 | **Demo mode**: when `EXPO_PUBLIC_API_URL` is unset the app serves bundled sample content (`src/lib/api/mock-data.ts`); when the Supabase vars are unset, sign-in is simulated on the device (staff sign-in shows admin tools) | Lets anyone build, test and demo the app with no keys or backend | Accepted. Never ship a store build without the env vars |
| D-017 | **Local builds without EAS**: `npm run ios:device` / `ios:sim` build a Release app with Xcode on the developer's machine, signed with `APPLE_TEAM_ID` from `.env` | Faster iteration than EAS cloud builds, no Expo Go limitations | Accepted. EAS stays available for store builds |
| D-018 | Data fetching through **TanStack Query** hooks (`src/lib/api/queries.ts`) over a typed `fetch` client | Caching, refetch on pull-to-refresh, loading/error states for free | Accepted |
| D-019 | Report categories expanded to the prototype's six (`abandoned_building`, `standing_water`, `air_odor` added); reports have `keepNamePrivate`; housing adds `home_repair` and `housing-listing` | Figma prototype screens | Accepted (see data-model.md) |
| D-020 | Route auth pattern: resident and admin routes use `auth: false` plus the `global::is-authenticated` / `global::is-admin` policies. Public reads keep Strapi's scope check, granted to the Public role at bootstrap, and a `supabase` content-API strategy maps signed-in users onto Public permissions | Supabase tokens would otherwise 401 on public core routes (plan 001, Q-A) | Accepted |
| D-021 | Backend tests run on a throwaway SQLite file per test file. JWTs are verified with `jose@^5` (CommonJS). `sharp` strips photo EXIF, so **HEIC blight photos are rejected** and the app sends JPEG | Fast CI without Docker; privacy of photo GPS data | Accepted |
| D-022 | Business rules (last-admin invariant, append-only activity log, blight `statusHistory`, reminder cleanup) live in Strapi **Document Service middleware**, so edits from the admin panel obey them too | One enforcement point for app and admin panel | Accepted |
| D-023 | External calls are opt-in: `PUSH_ENABLED`, `ENVIRONMENT_SYNC_ENABLED`, `AIRNOW_API_KEY`. District bounds come from `DISTRICT_BBOX` | Dev and test never hit external services | Accepted |
